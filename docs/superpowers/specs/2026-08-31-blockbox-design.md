# blockbox 설계 문서

작성일: 2026-08-31

## 개요

직육면체 통 내부로 조각이 떨어지는 3D 테트리스. 쿼터뷰 시점에서 스와이프로 조각을 옮기고, 버튼으로 회전한 뒤 하드드롭으로 떨어뜨린다. 모바일(안드로이드) 대상, Godot 4.6으로 만든다.

1차 목표는 개인용 플레이다. 완성도가 나오면 안드로이드 마켓 판매를 검토하되, 판매 관련 기능(광고, 결제, 리더보드)은 이 문서 범위 밖이다.

## 핵심 결정 사항

| 항목 | 결정 |
| --- | --- |
| 그리드 | 4(X) × 4(Z) × 14(Y), 진짜 3D 그리드 |
| 클리어 단위 | 층(layer). 한 층 16칸이 모두 차면 삭제 |
| 조각 | 1단계는 평면 테트라큐브 5종, 이후 비평면 3종 추가 |
| 이동 | 화면 상하좌우 스와이프를 카메라 기준 4개 축 방향에 배정 |
| 회전 | 버튼 4개. 수직축 양방향 + 나머지 두 축 각 한 방향 |
| 시점 | 직교 투영, yaw 4단계 고정, 회전 버튼으로 90도씩 전환 |
| 엔진 | Godot 4.6, GDScript |

## 좌표계와 데이터 모델

그리드는 정수 좌표만 쓴다. 원점은 바닥 한 귀퉁이이며, Y가 위쪽이다.

```
board: PackedInt32Array, 길이 224 (4 × 4 × 14)
인덱스 = y * 16 + z * 4 + x
값 0 = 빈칸, 1 이상 = 조각 종류 인덱스(색상으로 쓰임)
```

조각은 `Vector3i` 4개의 배열(`cells`)과 종류(`kind`)로 표현한다. 좌표는 조각 로컬 기준이며, 보드상 위치는 별도의 `origin: Vector3i`가 갖는다.

부동소수점을 로직에 쓰지 않는다. 회전은 축 하나를 기준으로 성분을 교환하고 부호를 뒤집는 정수 연산으로만 처리한다. 예를 들어 Y축 회전은 `(x, y, z) -> (z, y, -x)`다. 이렇게 하면 같은 축으로 4번 회전했을 때 원본과 정확히 일치하는 것이 보장된다. 이 성질은 테스트로 고정한다.

조각별 회전 피벗은 조각 정의에 함께 넣는다. O 조각처럼 기하학적 중심이 칸 경계에 걸리는 경우, 중심 대신 특정 셀을 피벗으로 고정해 회전 결과가 격자를 벗어나지 않게 한다.

## 조각 세트

3D 공간에서는 평면 조각의 거울상을 뒤집어서 겹칠 수 있다. 2D 테트리스의 S와 Z, J와 L은 각각 3D에서 같은 조각이 된다. 따라서 평면 조각은 7종이 아니라 **5종**이다.

**1단계 (5종, 평면)**: I, O, T, S, L

**2단계 (+3종, 비평면)**: 오른나사, 왼나사, 삼각(tripod). 앞의 두 개는 서로 거울상이며 3D 회전으로 겹칠 수 없는 별개의 조각이다. 총 8종이 되며, 이는 크기 4 폴리큐브의 전체 집합이다.

2단계는 1단계의 상위집합이다. 구현상으로는 조각 테이블에 항목 3개를 추가하고 랜덤 주머니 크기를 5에서 8로 바꾸는 것이 전부다. 언제 개방할지(레벨 조건, 별도 모드)는 플레이테스트 후 정한다.

## 게임 규칙

### 층 클리어

한 층 16칸이 모두 차면 그 층을 삭제하고, 위쪽 층 전체를 한 칸 내린다. 줄(4칸) 단위 클리어는 두지 않는다. 4×4 그리드에서 줄 클리어까지 인정하면 판이 너무 쉽게 비어 긴장이 사라진다.

한 조각이 여러 층에 걸쳐 동시에 층을 완성할 수 있다. 동시 클리어 배율은 1층 1배, 2층 3배, 3층 6배, 4층 12배다. 3D에서는 이것이 유일한 고득점 수단이므로 보상을 크게 잡는다.

### 조각 생성

랜덤 주머니(bag) 방식을 쓴다. 전체 조각 종류를 한 번씩 담아 섞은 뒤 하나씩 꺼내고, 주머니가 비면 다시 채운다. 같은 조각이 연속으로 나오지 않는다.

스폰 위치는 y=13, 중앙(x는 1~2, z는 1~2)이다. 다음 조각 1개를 미리 보여준다.

### 낙하와 잠금

중력 타이머가 만료될 때마다 한 칸 내려간다. 레벨 1의 낙하 간격은 1.0초이고, 레벨이 오를 때마다 짧아져 최소 0.15초에서 멈춘다.

주 조작은 **하드드롭**이다. 버튼을 누르면 조각이 바닥까지 즉시 내려가 잠긴다. 모바일에서 소프트드롭을 길게 누르는 조작은 불편하므로 두지 않는다.

**잠금 지연은 0.5초**다. 조각이 바닥이나 다른 블럭에 닿아도 즉시 굳지 않고, 그 사이 이동과 회전이 가능하다. 3D는 자리 판단에 시간이 더 걸리므로 2D 테트리스의 통상값보다 넉넉히 잡았다. 다만 이동이나 회전으로 지연을 갱신할 수 있는 횟수는 **15회로 제한**한다. 제한이 없으면 조각을 무한정 굳지 않게 버틸 수 있다.

하드드롭으로 내려간 조각은 잠금 지연 없이 즉시 잠근다.

### 게임 종료

새 조각을 스폰 위치에 놓을 수 없으면 게임이 끝난다.

### 레벨

층 클리어 누적 5개마다 레벨이 1 오르고 낙하 간격이 줄어든다.

### 난이도 조정 여지

16칸짜리 층은 2D 테트리스의 10칸짜리 줄보다 훨씬 채우기 어렵다. 첫 플레이테스트에서 "판만 차고 클리어가 거의 없다"는 결과가 나올 가능성이 있다. 조정 손잡이를 미리 상수로 빼둔다.

- `LAYER_CLEAR_THRESHOLD = 16` — 층 클리어에 필요한 칸 수. 14 등으로 낮추면 클리어가 잦아진다
- `GRID_WIDTH = 4`, `GRID_DEPTH = 4` — 3×3으로 줄이면 층이 9칸이 된다
- `BASE_FALL_INTERVAL = 1.0` — 초기 낙하 간격

셋 중 `LAYER_CLEAR_THRESHOLD` 조정이 가장 값싸다. 그리드 크기 변경은 UI 레이아웃과 스폰 위치에 파급된다.

## 조작

### 카메라

직교 투영을 쓴다. pitch는 30도이며, yaw는 45/135/225/315의 네 값 중 하나다. 카메라 회전 버튼으로 90도씩 전환하며, 전환은 0.25초에 걸쳐 보간한다.

원근 투영을 쓰지 않는 이유는 깊이 판단 때문이다. 원근에서는 안쪽 칸이 작게 보여 "저 자리가 몇 칸째인지"를 눈으로 셀 수 없다. 직교에서는 모든 칸이 같은 크기로 보여 셀 수 있다.

### 스와이프 이동

손가락을 끄는 동안 40픽셀마다 한 칸씩 이동한다. 손가락을 떼지 않고 계속 끌면 계속 이동한다.

화면 방향과 그리드 축의 대응은 카메라 yaw에 따라 결정된다. 사용자 입장에서는 카메라를 어떻게 돌리든 항상 다음이 성립한다.

- 위로 끌기 = 화면 안쪽(먼 쪽)
- 아래로 끌기 = 화면 앞쪽(가까운 쪽)
- 좌우로 끌기 = 화면 좌우

이 매핑이 시점 회전과 함께 돌아가지 않으면 회전 후 조작이 뒤집혀 게임을 할 수 없게 된다. 반드시 지켜야 할 불변 조건이다.

### 회전 버튼

버튼 4개를 둔다.

- 수직축(화면 기준 위아래 축) 반시계
- 수직축 시계
- 가로축 눕히기
- 세로축 눕히기

수직축 회전은 사용 빈도가 압도적으로 높아 양방향을 준다. 나머지 두 축은 조각을 눕히거나 세우는 용도라 한 방향이면 충분하며, 반대 방향이 필요하면 세 번 누른다.

**회전축은 카메라 기준이다.** 카메라를 90도 돌리면 회전축도 함께 돌아간다. 스와이프 매핑과 동일한 원칙이다.

### 회전 킥

회전 결과가 벽이나 이미 쌓인 블럭과 겹치면 조각을 한 칸씩 밀어 재시도한다. 시도 순서는 다음과 같다.

1. 수평 4방향 (+X, -X, +Z, -Z)
2. 아래(-Y)
3. 위(+Y)

모두 실패하면 회전을 취소한다. 위로 미는 것을 마지막에 두는 이유는, 조각이 위로 밀리면 예상 착지 지점이 크게 달라져 플레이어의 예측이 깨지기 때문이다.

### 버튼 배치

- 화면 하단: 회전 4개, 하드드롭 1개
- 화면 상단: 카메라 회전 2개

카메라 버튼을 상단으로 분리한 이유는, 게임 조작과 시점 조작이 인접하면 오입력이 나기 때문이다.

## 깊이 표시 장치

쿼터뷰 3D 테트리스의 가장 큰 실패 원인은 "조각이 어디에 떨어질지 모르겠다"는 것이다. 다음 네 가지를 필수로 넣는다.

1. **고스트 조각** — 지금 하드드롭하면 착지할 자리에 반투명 조각을 그린다. 가장 중요한 장치다.
2. **바닥 발자국** — 조각이 차지하는 XZ 칸을 바닥 격자에 밝게 칠한다. 고스트가 다른 블럭에 가려도 이것은 항상 보인다.
3. **층 게이지** — 화면 옆에 14개 층 막대를 세로로 놓고, 각 층이 몇 칸 찼는지(n/16) 표시한다. 어느 층을 노려야 하는지는 3D 화면만 봐서는 셀 수 없다.
4. **바닥 격자선** — 4×4 격자를 바닥에 상시 표시한다.

벽면 투영(Blockout 방식)은 넣지 않는다. 화면이 복잡해지고, 카메라 회전이 같은 문제를 더 낫게 해결한다.

## 코드 구조

의존 방향은 한 방향이다. `board`/`piece`는 아무것도 참조하지 않고, `game`이 이 둘을 쓰며, 뷰와 HUD는 `game`의 상태를 읽기만 하고, 입력은 `game`에 명령을 보낸다. 역방향 참조는 없다. 따라서 `board`/`piece`/`game`은 씬 없이 테스트할 수 있다.

```
scripts/
  board.gd          RefCounted. 그리드 배열, is_valid(cells), lock(piece), clear_layers() -> int
  piece.gd          RefCounted. 조각 테이블, rotate(axis, dir), 킥 시도 순서
  game.gd           Node. 중력 타이머, 잠금 지연, 랜덤 주머니, 점수/레벨, 게임오버.
                    신호: piece_moved, piece_locked, layers_cleared, game_over
  board_view.gd     Node3D. 잠긴 블럭을 MultiMeshInstance3D 하나로 렌더. piece_locked에만 갱신
  piece_view.gd     Node3D. 현재 조각 4큐브 + 고스트 4큐브 + 바닥 발자국. 고정 노드, 위치만 갱신
  camera_rig.gd     Node3D. yaw 4단계 관리, 화면 방향에서 그리드 축으로의 매핑 제공
  touch_input.gd    Node. 드래그 40px당 1칸, 버튼 입력을 game 명령으로 변환
  hud.gd            CanvasLayer. 층 게이지, 점수, 다음 조각, 버튼 7개
  main.gd           조립

scenes/
  main.tscn, hud.tscn

tests/
  test_board.gd, test_piece.gd, test_game.gd, test_camera_rig.gd
```

### 렌더링 방침

잠긴 블럭은 `MultiMeshInstance3D` 하나로 그린다(인스턴스 상한 224). 현재 조각과 고스트는 고정된 노드 8개를 두고 위치만 옮긴다. 매 프레임 노드를 생성하고 해제하는 방식은 모바일에서 프레임 드랍의 주요 원인이므로 쓰지 않는다.

### 축 매핑의 소유권

화면 방향과 그리드 축의 대응은 `camera_rig.gd`가 단독으로 소유한다. `touch_input.gd`도 회전 버튼 처리도 이 함수를 통해서만 축을 얻는다. 스와이프 매핑과 회전축 매핑을 각자 계산하면 시점 회전 후 둘이 어긋나는 버그가 생긴다. 계산 지점을 하나로 두어 그 버그를 구조적으로 차단한다.

## 테스트

기존 `turret-defense` 프로젝트와 같은 방식을 쓴다. `extends SceneTree` + `_initialize()` + 순수 `assert`이며, 헤드리스로 실행한다.

```
godot --headless --script tests/test_board.gd
```

핵심 검증 항목:

- `test_piece.gd` — 모든 조각과 모든 축에 대해 같은 축 4회 회전이 원본과 일치. 킥이 벽 밖이나 점유된 칸을 허용하지 않음
- `test_board.gd` — 층 클리어 후 위층이 정확히 한 칸 내려옴. 여러 층 동시 클리어가 올바르게 처리됨
- `test_game.gd` — 잠금 지연 갱신이 15회에서 멈춤. 스폰 위치가 막히면 게임오버
- `test_camera_rig.gd` — yaw 네 단계 모두에서 "위로 끌기 = 화면 안쪽"이 성립

## 개발 순서

각 단계는 이전 단계의 테스트를 깨지 않는 상태로 끝낸다.

1. `piece.gd` + `board.gd` + 테스트 (화면 없음, 전부 헤드리스)
2. `game.gd` + 테스트 (여기까지 그래픽 코드 없음)
3. 최소 렌더 + 키보드 조작 — **데스크탑에서 처음 플레이 가능**
4. `camera_rig.gd` + 시점 회전
5. 터치 입력 (키보드 조작은 디버깅용으로 유지)
6. 깊이 표시 4종
7. 플레이테스트 후 상수 튜닝
8. 폴리시: 사운드, 클리어 이펙트, 최고점수 저장

3단계를 앞으로 당긴 것이 이 순서의 핵심이다. 터치와 카메라 회전을 모두 구현한 뒤에야 "4×4×14가 재미없다"를 발견하면 되돌릴 코드가 너무 많아진다. 그래픽이 최소인 상태에서 게임성을 먼저 확인한다.

## 안드로이드 대비

지금 해두면 추가 비용이 없는 것만 처리한다.

- 세로 모드 고정, 스트레치 모드는 `canvas_items`. 나중에 바꾸면 UI를 전부 재배치해야 한다
- 입력은 처음부터 `InputEventScreenDrag`와 `InputEventScreenTouch`로 처리한다. 마우스 이벤트에 의존하면 나중에 다시 써야 한다
- 최고점수는 `user://`에 저장한다

범위 밖(판매를 결정한 뒤에 착수): 광고, 인앱결제, 리더보드, 계정, 다국어.

## 상표 주의

"Tetris"는 Tetris Holding의 등록상표이며, 이 회사는 상표권 행사에 매우 적극적이다. 마켓에 올릴 경우 게임 이름, 스토어 설명, 스크린샷 어디에도 "Tetris" 또는 "테트리스"를 쓰면 안 된다.

게임 규칙 자체는 저작권 보호 대상이 아니므로 문제가 없다. 다만 이름, 조각 색 배합, 로고가 원작을 직접 연상시키면 스토어에서 내려갈 수 있다. 개인적으로 플레이하는 동안에는 해당하지 않으며, 마켓 등록 시점에 확인하면 된다.

## 범위 밖

이 문서는 다음을 다루지 않는다.

- 홀드(hold) 기능 — 플레이테스트 후 필요성이 확인되면 검토
- 여러 개의 다음 조각 미리보기 — 1개로 시작
- 멀티플레이, 온라인 기능 일체
- 튜토리얼 — 조작이 확정된 뒤에 만든다
